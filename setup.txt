Guided setup (manual docker run commands)
Check Docker is running

docker info
Build the AI agent image (run inside the openai-support-agent-demo folder)

docker build -t ai-agent -f Dockerfile.agent .
This bundles the app code and the Prisma schema into an image called ai-agent.

Create the shared network

docker network create support-net
Containers on this network can reach each other by name.

Start PostgreSQL

docker run -d --name demo-db --network support-net `
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres `
  -e POSTGRES_DB=support_agent_demo -p 5434:5432 postgres:16
Host port 5434 forwards to PostgreSQL’s 5432 inside the container.

Start Redis

docker run -d --name demo-redis --network support-net `
  -p 6380:6379 redis:7
The missing redis:7 image in your earlier command caused the “requires at least 1 argument” error.

Confirm both services are running

docker ps
Run the AI agent

docker run --rm --network support-net -p 3001:3001 `
  -e OPENAI_API_KEY=<your-openai-key> `
  -e CHATWOOT_APP_TOKEN=<your-chatwoot-token> `
  -e DATABASE_URL=postgresql://postgres:postgres@demo-db:5432/support_agent_demo `
  -e REDIS_URL=redis://demo-redis:6379 `
  ai-agent
Replace the placeholders with real keys. The previous P1012 Prisma error came from using … instead of a proper postgresql:// URL.

Test the agent

Visit http://localhost:3001 in your browser.

If everything worked, you should see the agent’s API responding.

Optional: Use docker-compose
Fix the last line of docker-compose.agent.yml so it ends with:

networks:
  support-net:
    external: true
Launch the whole stack:

docker network create support-net   # run once
docker compose -f docker-compose.agent.yml up -d
This automatically starts PostgreSQL (demo-db), Redis (demo-redis), Ollama, and the AI agent on the same network.

Stop individual containers

docker stop demo-db demo-redis ai-agent
Use the names from docker ps. Stopping kills the running process but keeps the container for later.

Remove containers (optional)

Removes the containers entirely so they won’t restart accidentally.

Tear down the shared network (optional)

Only needed if you want to clean up the custom network.


*Running only the AI agent stack*
Create the network once (if not already present):

docker network create support-net
Build the agent image from the agent‑only compose file:

docker compose -f docker-compose.agent.yml build ai-agent
Start the agent and its dependencies (Postgres 5434, Redis 6380, Ollama 11434):

docker compose -f docker-compose.agent.yml up -d
This file maps the ports so they do not conflict with your existing Chatwoot stack

Follow the logs to verify startup:

docker compose -f docker-compose.agent.yml logs -f ai-agent
Populate .env.ai with your actual keys and Chatwoot URL before building (OpenAI key, Chatwoot tokens, etc.)


Safely stopping the stack
To halt the containers and remove them (but keep volumes/data):

docker compose -f docker-compose.agent.yml down
This stops the agent, Postgres, Redis, and Ollama services and detaches from the support-net network.

If you only want to pause the containers without removing them:

docker compose -f docker-compose.agent.yml stop
Restarting later
To bring everything back up in the background:

docker compose -f docker-compose.agent.yml up -d
Cleaning up (optional)
If you no longer need the volumes or network, you can remove them explicitly:

docker volume rm openai-support-agent-demo_postgres_data \
                 openai-support-agent-demo_redis_data \
                 openai-support-agent-demo_ollama
docker network rm support-net
Use the down/stop commands when you're done working; up -d will start the stack again when you're ready.
